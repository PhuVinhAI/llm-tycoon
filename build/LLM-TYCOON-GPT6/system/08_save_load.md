# Save and Load

Use the canonical files and transaction protocol in `runtime/00_runtime_contract.md`. The full save follows `runtime/02_state_schema.md`.

Commit all mechanical transitions and checkpoints before presenting results. Also persist form drafts, interview candidates, pending choices, unfinished phase, and current view needed for exact resume. Never keep a newer state only in a chat message.

Generate a downloadable portable save ZIP on request and at the end of each in-game June and December. Exports do not advance time. Python sandbox files may expire; a downloadable artifact is how the player carries progress between sessions.

On startup with a save, validate and resume its language and active view, including a pending S10, S6, S12, or S16. Recover a journal first. Do not boot a new game or replay the saved month.

Trust accumulated Cash, RP, Fame, dates and completed history. Do not reconstruct past expenses and charge them retroactively. Document hard-cap repairs; preserve the original import. For schema/version mismatch or unresolved structural errors, stop the load instead of inventing state.

Recompute derived skill levels from counters and hardware totals from inventory/streams according to Rules. Validation must not replay past actions.

Import JSON or a portable ZIP with Python. A JSON-only import has no earlier history; disclose that gap and begin logging from the import. Never claim the transcript or a summary fills it.

Use `ui/04_save_format.md` for exports. Accept only version 1.0.0 and schema `llm-tycoon.save.v1`. Offer actual files, not a request for the player to manually paste a replacement prompt.
