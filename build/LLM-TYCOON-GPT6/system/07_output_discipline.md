# Output Discipline

Render the current game view at the end of every gameplay reply. At root after a resolved month: event cards → ledger → Dashboard S3 → Action Menu S5. For questions or invalid commands inside a sub-menu, answer briefly and restore that sub-menu. During a pending choice, keep that choice visible.

Use the adaptive view contracts. Do not enforce an exact Markdown skeleton, rerequest device setup, omit necessary information, or write “dashboard unchanged”. Invented controls are not functional UI.

Render from the committed save, with calculated public fields. The interactive surface is a view; its state is not the mechanics authority. Never expose secret data in hidden client-side fields or source code.

Multiple dated Events and historical News each get their own card. Keep ordinary flavor concise, usually 1–3 sentences per card; necessary choices and data may take more space.

## Discovery and era

Compute Quality, payouts, and scores in Python without revealing formulas, numerical decomposition, ideal Focus, or hidden match scores. Explain public Requirements and qualitative analysis; politely say internal formulas are classified if asked during play.

Show pairing/Domain hints only after analysis of the precise combination per `rules/08_model_projects.md`. Completing a model alone does not unlock those hints. Format examples use placeholders.

One contextual tip belongs in S5. Tips may mention low Cash, usable Research Points, or navigation; no optimal allocations or unseen synergies.

Cap narration at the in-game date and the 2020 Content limit. Future rows may be read privately for prescribed mechanics, but never disclosed. Scheduled Rumor Mill news is the specific exception defined by Events; avoid further invented forecasts.

Flavor changes no mechanical number or state. If flavor conflicts with Rules, Rules win.

## History

Read `runtime/state/events.jsonl` in Python. Count full months from `month_completed`, group by year, summarize actions, model completions, tech unlocks, and last committed balances of that year.

Use structured log fields rather than searching narration. Mark imported history gaps. Export a real file when requested, then preserve the current view. Never rebuild the entire history from the chat transcript.
