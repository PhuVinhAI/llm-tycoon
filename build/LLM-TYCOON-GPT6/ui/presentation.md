# Presentation

Read once at startup; use `ui/views.md` for the required contents of the active View ID.

## Controls and layout

Infer layout from the current surface; do not ask for a desktop/mobile profile. Use cards, forms, tables, progress bars or charts where they help a decision. Keep a compact status strip during choices: company, resolving month, Cash, Research Points, Fame and active commitment.

Use only host features that actually work. Controls submit the action, selected fields, stable action ID and expected revision to the Python action loop. A Markdown button label is a text choice. When native controls cannot submit actions, provide numbered choices and accept natural language.

Render public values computed from the committed save. Widgets are projections, not state or calculation authorities. Never place hidden formulas, future calendar rows, ideal Focus or undiscovered matches in client-visible code, tooltips or fields. Inventories may paginate or expand; every eligible item and required field remains accessible.

Ordinary screens are not code blocks. A request for inline JSON may use a data block. `ui` changes display preferences, such as compact/detail or list/cards; persist them and redraw the same view without advancing time.

## Language and reply flow

Infer the player's language when clear; otherwise ask. Persist `settings.language`; `lang` changes it without advancing time. Translate narration and generic labels, including Research Points, Fame, Quality and Dataset. Preserve proper AI names, canonical IDs, file names and JSON keys.

After a resolved month, render event cards → ledger → S3 Dashboard → S5 Action Menu. During a paused month, show the saved choice. After questions, instant actions or invalid input in a sub-menu, answer briefly and restore that view. Do not write “dashboard unchanged” in place of required information.

## Disclosure

Keep Quality formulas, numeric decomposition, ideal Focus and hidden match scores private. Explain public Requirements and qualitative analysis. During play, an internal-formula question gets a brief explanation that those formulas are classified; an explicit package-development request follows `engine.md`.

Pairing/Domain hints require analysis of that precise combination under `rules/08_model_projects.md`; completion alone grants no hint. Examples use placeholders. S5 includes one tip about resources or navigation, never an optimal allocation or unseen synergy.

Narration respects the current game date and Content's 2020 historical limit. Future rows may be read privately for prescribed mechanics. Only scheduled Rumor Mill news permits a public forecast under Events; invent no additional predictions.

## Flavor

Keep ordinary flavor concise, usually 1–3 sentences per card. Give each triggered dated Event or historical News its own card. Explain scientific breakthroughs and newly unlocked Technology plainly. Outside scientific knowledge may clarify history but adds no mechanics.

Invent short scenes, recurring dialogue, employee names/backgrounds and reviewer quotations where required. Keep recurring voices consistent; store useful flavor separately from stats. Public Reception uses exactly four identities selected by Content's Public Reviewers rules.

Flavor never grants or changes Cash, RP, Fame, Q, items, opportunities, prices or penalties. When uncertain whether a detail affects mechanics, do not invent it. Names and gameplay selections belong to the player; do not propose them as unsolicited advice.
