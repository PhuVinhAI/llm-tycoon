# Worked Example — illustrative only

A Research request at the root view:

1. Python loads the save and relevant month, Research, Economy, Skills, Events, and staff documents.
2. GPT-6 computes the deterministic dilemma choices in Python.
3. It commits any already-fired Events, plus S10, the exact pending choices, accumulated ledger, and the next uncompleted phase.
4. It renders two public choices as working controls or numbered options and waits.
5. The player selects one. Python reloads that saved pending state, applies only the selected outcome, then resolves the remaining Streams, Costs, Completions and Checks once.
6. It commits the full month report and next decision month, then renders S4 → S3 → S5.

Reattaching a save at step 4 shows the same choice with the same mechanical effects. It does not fire Events again or charge the month before the choice is made.

A completed-model view can use a comparison table for all benchmark results, a Quality card, and four release choices. The layout can adapt while preserving every required S6 field. Completion RP is already recorded; selecting Release awards only the documented release effects.

This example introduces no numeric rules or exceptions.
